# UI 0.0.2

## Vue hydration fix

Vue native HTML void elements, including `input` and `hr`, no longer receive
default slot children from the UI factory. In 0.0.1, a forwarded empty slot
produced a Fragment that SSR omitted but the client tried to hydrate, causing
children-mismatch warnings and inserting invalid child anchors.

The published 0.0.1 issue was reproduced in Calendar, Clipboard, Color Picker,
Combobox, Dynamic, File Upload, Menu, Number Input, OTP Input, Signature and
Slider examples. The local fix passed SSR and hydration for all 46 Vue design
examples with no diagnostics. Focused checks retained element identity, focus,
callbacks, reactive updates and cleanup; no broader functional failure was
demonstrated in the affected published examples.

The fix applies only to native HTML void tags. It preserves `asChild`, dynamic
component selection, non-void children, custom components and SVG behavior.
Twenty-seven factory regressions cover these boundaries.

## Upgrade

Explicitly update `@destyler-ui/vue` to `0.0.2` (or `^0.0.2`) and refresh the
lockfile. The range `^0.0.1` does **not** include `0.0.2`. Consumers using multiple
Destyler UI framework packages can update them together.

All four public packages use version 0.0.2 under the existing synchronized
release policy. React, Solid and Svelte have no runtime changes in this release.
Core dependency ranges remain `^0.3.3`, the exact-core compatibility gate remains
on 0.3.3, and Node >=22.22.3 remains required. No API migration is required.
